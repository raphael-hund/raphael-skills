## 1. Ziel + Vertrag

Ein Web-Skill, bei dem Faulheit technisch unmöglich ist: screenshot-basiert, bildererzeugend, kreativ pro Element, SEO integriert — und jede dieser Pflichten wird von einem Skript oder Hook geprüft, nicht von Prosa erbeten.

**Vertrag (prüfbare Kriterien):**
1. „Fertig" ist ohne frisches `manifest.json` + Nachweis „jedes PNG angesehen" + `visual-ship.json` mechanisch unmöglich (Hook blockt).
2. Keine Seite shippt mit Platzhaltern, ungenutzten guten Assets oder Bild-Doppelungen (`bild-gate.mjs` Exit 0 Pflicht).
3. Vor dem ersten Code-Edit existiert ein Recherche+Design-Brief (Firma recherchiert, aktuelle Website gescreenshottet, Asset-Inventar, feste Design-Idee je Sektion) — `brief-gate.mjs` Exit 0.
4. Bild-Workflow mit Kontext- vs. Style-Referenzen ist als 5-Befehls-Rezept + Index-Pflichtfeld verdrahtet.
5. SKILL.md ≤ 130 Zeilen; die Detail-Doktrin bleibt in references, wird aber nur noch on-demand geroutet.
6. Grok-Logik-Review der neuen Skripte/Hooks: pass; Eval `screenshot-loop` aktualisiert (1400→1500) und grün.

## 3. Lösung — Architektur

**Kein Neuschreiben der Doktrin. Umbau auf: dünner Vertrag + deterministische Gates.**
Bestehende Skripte bleiben Kern (`shot-sweep.mjs`, `bilder.mjs`, `detect.mjs`, `werkzeug-gate.mjs`). Neu sind drei Gates, zwei Hooks und ein schlankes SKILL.md.

### 3.1 Die Pipeline (bindend, eine Zeile)

recherche+brief (`brief-gate`) → sitemap/section-plan mit SEO-Feldern + Asset-Plan → copy → art-direction (feste Design-Idee je Sektion) → components (Werkzeugtabelle) → build Element für Element → Screenshot-Loop (sweep → jedes PNG Read → Panel/Blind-A/B → Fix → **Re-Sweep alle Routen**) → `bild-gate` + QA-Fächer → visual-aaa → Signatur.

### 3.2 Neue Gates (Skripte, alle in `web/scripts/`)

**a) `brief-gate.mjs`** — Exit ≠ 0, solange `art-direction.md` (bzw. `design-brief.md`) nicht enthält:
- Block `## Firma` (Recherche: was macht die Firma, Quelle, Screenshot-Pfade der aktuellen Website),
- Block `## Asset-Inventar` (jede Datei aus Eingang/assets mit Entscheidung nutzen/verwerfen+Grund),
- Block `## Design-Idee` mit einer benannten Idee **pro Sektion** (keine zwei identischen Ideen direkt nacheinander),
- Block `## Bild-Policy` (erlaubt der Kunde KI-Bilder? Beweis-Kontexte immer echt),
- 4-Felder (Colors/Style/Composition/Use case) je geplantem Generat.
Prüfung grep-/struktur-basiert, kein LLM. **Gegen Form-Grün (Grok-Fund 6):** jeder im Brief genannte Screenshot-Pfad muss als Datei existieren; das Asset-Inventar wird 1:1 gegen die echte Dateiliste des Eingangs-/Asset-Ordners abgeglichen (fehlende Datei im Brief = rot).

**b) `bild-gate.mjs`** — Exit ≠ 0 bei (alles maschinenklar, Grok-Fund 7 eingearbeitet):
- Platzhalter-Mustern im Code/Assets (`ph-*`, „PLATZHALTER", leere alt-Attribute, Unsplash-Hotlinks),
- Bild im Code referenziert, aber nicht in `bilder-index.json` (oder Index-Eintrag `TBD`),
- fehlendem Pflichtfeld `referenz-typ` (`kontext`/`style`/`beides`/`ohne`) bei generierten Bildern,
- Bild-Doppelung: gleiche Datei >1× pro Seite oder >2× sitewide (Salsaflow-Regel, generalisiert),
- Asset-Plan (maschinenlesbar: `asset-plan.json`, je Sektion `bild: pflicht|optional|keins`) verlangt Bild für Sektion X, Code hat keins,
- Inventar-Datei ohne Entscheidung im Brief (verwendet ODER verworfen+Grund) — „brauchbar" entscheidet der Agent im Brief, das Gate prüft nur Vollständigkeit der Entscheidungen.
Voraussetzung: Index-Schema (`referenz-typ`) und `asset-plan.json`-Schema werden **vor** dem Gate fixiert (siehe Etappen-Reihenfolge).

**c) `sweep-gate.mjs`** — Exit ≠ 0 bei (Grok-Fund 8 eingearbeitet):
- kein `manifest.json` jünger als der letzte Edit unter den Watch-Globs `src/`, `app/`, `components/`, `pages/`, `styles/`, `content/`, `public/` (breite Globs statt src-only),
- Manifest-PNG nicht im View-Ledger (siehe Hook 1) → „nicht angesehen",
- Sweep ohne `--static` bei Kritik-Läufen,
- fehlende Mobile-Shots — nur im **Ship-Modus**; Ship-Modus ist explizit: Datei `.ship-intent` im Projekt-Root (legt der Agent an, wenn er ausliefern will) oder Flag `--ship`.
`shot-sweep.mjs` schreibt zusätzlich `.web-last-sweep` (absoluter OUT-Pfad + Zeitstempel) ins Projekt-Root — die eine kanonische Quelle für Gate und Hooks.

### 3.3 Hooks (Enforcement-Schicht)

**Hook 1 — View-Ledger (global, PostToolUse auf Read):** Liest der Agent ein PNG, hängt der Hook den Pfad an `.viewed.log` **im Verzeichnis des PNGs** (`dirname(file_path)`) — der Hook braucht so kein Wissen über den Sweep-Out-Pfad (Grok-Fund 1). `sweep-gate.mjs` findet den Sweep über `.web-last-sweep` und vergleicht Manifest gegen `.viewed.log` daneben.

**Hook 2 — Done-Guard (Projekt-Template, Stop-Hook):** Scharf nur in Projekten mit Marker-Datei `.web-project` (legt der Skill beim Init an) UND wenn `.ship-intent` existiert (Grok-Fund 4 — kein Raten über „Fertig-Behauptung"). Dann blockt Stop, solange `sweep-gate`/`bild-gate` rot sind oder `visual-ship.json` fehlt/älter als der letzte Edit ist. Der Block-Text nennt IMMER den exakten Befehl, der grün macht. Ohne `.ship-intent` darf die Session normal enden (kein Deadlock bei Zwischenständen).

**Hook 3 — Ad-hoc-Shot-Blocker (Projekt, PreToolUse):** Eng gefasst (Grok-Fund 5): blockt nur `page.screenshot`, `captureBeyondViewport`, `fullPage: true` in Bash-Kommandos; Allowlist: Aufrufe von `shot-sweep.mjs` bzw. `web/scripts/` sowie `playwright install`/`playwright test`. Zusätzlich Matcher auf MCP `browser_take_screenshot` (der zweite reale Umgehungsweg). Block-Text: „Standard-Skript fixen statt Ad-hoc-Skript schreiben."

**Hook 4 — Brief-Guard (Projekt-Template, PreToolUse auf Edit|Write):** Blockt Edits unter `src/`, `app/`, `components/`, `pages/`, solange `brief-gate.mjs` rot ist — damit ist „Brief vor erstem Code-Edit" erzwungen, nicht erbeten (Grok-Fund 3). Config-/Doku-/Script-Dateien bleiben frei.

**Anti-Deadlock (gilt für alle Gates/Hooks, Grok-Fund 9):** Jeder Block nennt den Grün-Befehl. Nach 3 roten Läufen desselben Gates in Folge: zwingend `BLOCKED`-Report mit Artefakt an Raphael; Override nur per Token-Datei `.gate-override` mit Raphaels Wort + Ablaufdatum.

**Nein-Protokoll (mechanisch):** Raphael-Nein → Verboten-Eintrag in Root-`DESIGN.md`/`DECISIONS.md` **plus**, wenn maschinell prüfbar, sofort ein Detektor im Projekt (Build-Gate nach Wilhelm-Video-Muster). Der Skill führt dafür eine kleine Vorlage (`verbots-gate.template.mjs`).

### 3.4 Bild-Workflow v2 (Referenz `bildgenerierung.md`, geschärft)

- **Modell-Matrix (unverändert bestätigt durch Raphael 11.08.):** Prototyp/Preview → Higgsfield `nano_banana_flash` (Banana/Banana Light), **sonst immer GPT Image 2** (`gpt_image_2` via hf CLI). Recraft nur fotorealistisch ohne jede Referenz.
- **Referenz-Typen als Pflichtdeklaration:** jedes Generat deklariert `kontext` (WAS: Person, Logo, Produkt, Szene) und/oder `style` (WIE: Shooting-Look, Palette, Licht) — landet als `referenz-typ` + `referenzen` im Bild-Index, `bild-gate` prüft.

- **Bild-Policy pro Projekt:** KI-Personen/Szenen erlaubt, wenn Kunde zustimmt (Sorglos: ja, Wilhelm: nein) — steht im Brief; **Beweis-Kontexte (Team, Testimonials, Vorher/Nachher) IMMER echt**, projektunabhängig. Uncanny-/Klon-Check vor Index-Aufnahme.
