### Scroll-Reveal-Muster

Klassen wie `aos-init`, `fade-up` oder `reveal` existieren nicht. Das Muster ist `IntersectionObserver` plus direkte Style-Änderung. Wörtlich aus `home.html`:

```js
const observer = new IntersectionObserver((entries, observer) => {
    entries.forEach(entry => {
        if (!entry.isIntersecting) return;
        entry.target.querySelectorAll(".haubner-ranking__fill").forEach(bar => {
            bar.style.width = bar.dataset.progress + "%";
        });
        observer.unobserve(entry.target);
    });
}, {
    threshold: 0.3
});
```

Stagger gibt es nicht, alle Balken einer Gruppe starten gleichzeitig. Die Breite kommt aus `data-progress` im HTML, etwa `data-progress="15"`.

### 3. Animation-Rezepte

7 Rezepte, alle Werte wörtlich aus den abgerufenen CSS- und HTML-Dateien. Wo ein Wert nur zur Laufzeit entsteht, steht das ausdrücklich dabei.

**Rezept 1: Hero-Bildwechsel mit Lottie-Sync (exakte Werte belegt)**

Das ist die aufwendigste Animation der Seite. Zwei Bilder und zwei Buttons laufen in einem 10-Sekunden-Zyklus, das zweite Paar startet bei 50 %. Werte wörtlich aus `post-5.css`:

```css
.hero-img-btn-1  { animation: heroButton1 10s cubic-bezier(0.22, 1, 0.36, 1) infinite; }
.hero-img-main-2 { animation: heroImage2 10s cubic-bezier(0.22, 1, 0.36, 1) infinite; }
.hero-img-btn-2  { animation: heroButton2 10s cubic-bezier(0.22, 1, 0.36, 1) infinite; }
```

Basiszustand und Keyframe, wörtlich:

```css
.hero-img-main-1, .hero-img-main-2 { opacity: 0; transform: translateY(90px); pointer-events: none; }

@keyframes heroImage1 {
  0%   { opacity: 0; transform: translateY(90px); }
  8%   { opacity: 1; transform: translateY(0); }
  42%  { opacity: 1; transform: translateY(0); }
```


Der Trick: `pointer-events` wird innerhalb der Keyframes mitanimiert, damit der unsichtbare Button nicht klickbar bleibt. Die drei Zustände sind Ankommen (0 auf 8 %), Halten (8 auf 42 %) und Verlassen (42 auf 50 %), dann Pause bis 100 %, während das zweite Paar ab 50 % übernimmt.

### 4. Anti-Patterns und Schwächen

**1. FAQ-Akkordeons ohne FAQPage-Schema.** Alle Seiten haben FAQ-Blöcke, die Startseite 7 Fragen, die Verkaufsseite ebenfalls, die Kontaktseite eigene. Keine einzige Seite hat `FAQPage` in `ld+json`. Beleg: Zählung über alle 11 gefetchten HTML-Dateien ergibt `FAQPage: 0` für jede. Der Inhalt liegt in nativen `<details>`-Elementen und ist damit technisch korrekt, aber für Rich-Results ungenutzt.

**2. Kaputte canonical-URL auf Blogartikeln.** In `blogartikel.html` steht wörtlich:

```html
<link rel="canonical" href="https://www.haubnergroup.deblog/haus-kaufen-kosten/" />
```

Der Schrägstrich vor `blog` fehlt, die Domain ist `www.haubnergroup.deblog`. Das ist ein Fehler im Yoast-Output oder in der Permalink-Konfiguration und betrifft potenziell alle 37 Posts.

**3. Nicht parsebares JSON-LD.** Auf der Startseite und der Angebotsseite gibt es je ein `ld+json`, das kein gültiges JSON ist. Fehlermeldung: `Invalid \escape: line 1 column 517 (char 516)`. Der Inhalt ist eine `ItemList` mit Immobilien-Teaser-Objekten. Ein `\`-Zeichen in einem String ist nicht escaped, der gesamte Block fällt damit für Crawler aus.

**4. Kein Consent-Tool bei zwei aktiven Analytics-Properties.** Im HTML gibt es weder Cookie-Banner-Markup noch ein Consent-Script. Gefunden wurden null Treffer für cookieyes, borlabs, usercentrics, consentmanager, complianz, iubenda, klaro, osano und termly. Gleichzeitig laufen `gtag` mit `GT-K8MZTTXV` und, nachgeladen aus einem Fremd-Script, eine zweite GA4-Property `G-C5WNL16X6S`. Auf der Seite selbst steht ein Bewertungshinweis zur Transparenz, aber keine Einwilligungsabfrage.

**5. Reduced-Motion greift nicht für die Hauptanimation.** Der Block in `post-5.css` schaltet nur `transition` ab:

```css
@media (prefers-reduced-motion: reduce) { * { transition: none !important; } }
```

Die Hero-Keyframes laufen weiter, weil `animation` nicht mit abgeschaltet wird und der Block vor den Keyframe-Definitionen im selben Stylesheet steht. Nur das Marquee-Plugin hat einen korrekten eigenen Block mit `animation: none`.

**6. Abweichende Kontaktdaten innerhalb derselben Seite.** Der Footer nennt "Konsul-Smidt-Str. 90", die Kontaktseite im Kontakt-Hero "Konsul-Schmidt-Str. 90". Beim Telefon gibt es drei Nummern: "0421 - 5177 5177" im Header und Final-CTA, "0421 – 1751 6087" als Eigentümer-Direktdurchwahl, "0421 – 5177 5177" mit Gedankenstrich statt Bindestrich in manchen Blöcken. Der Footer schreibt kompakt "0421-51775177" ohne Leerzeichen.

**7. Eine Sektion ist auf allen Geräten ausgeblendet, bleibt aber im DOM und in der Dateigröße.** Die Sektion "Was nach Ihrer Bewertung passiert – Sie bestimmt das Tempo." auf der Rechnerseite trägt alle vier Hidden-Klassen. Mit 20.019 Bytes bleibt sie vollständig im HTML und wird nur per CSS versteckt.

**8. Fehlende H1 auf der Kontaktseite.** `kontakt.html` hat `H counts: {2: 10, 3: 4}`, also keine H1. Die Seite beginnt inhaltlich mit H2 "Wir sind für Sie da.". Gleiches Muster bei der Blog-Übersicht wäre vorhanden, dort existiert aber eine H1 "Der HAUBNER GROUP Ratgeber".

**9. Standortseiten sind die schwersten Seiten der Website.** `standort.html` ist mit 1.779.505 Bytes die zweitgrößte gefetchte Datei nach der Verkaufsseite, bei nur 8 eigenen H2. Ursache ist vor allem die Objektliste in Sektion 8 mit 383.349 Bytes in einem einzigen Container und 26 Bildern. Bei 40+ Standortseiten, die alle dieselbe Objektliste einbinden, entsteht daraus ein erheblicher Wartungs- und Ladeaufwand. Die Testimonials- und Auszeichnungs-Sektion ist dabei korrekt einmal vorhanden, sie wird über ein Elementor-Template (`data-elementor-id="3581"`) eingebettet und liegt deshalb verschachtelt vor.

**10. `fetchpriority="high"` sitzt auf den falschen Bildern.** Pro Hauptseite trägt genau 1 Bild das Attribut, auf der Startseite ist es `Offizielles-Regio-Partner-Siegel-des-SV-Werder-Bremen.webp`, also ein Siegel weit unterhalb des Heros. Auf `/angebote/` und `/kontakt/` ist es `haubner_team_jonas.png`, auf `/fallstudien/` sind es 7 Vorkommen desselben Rahmengrafik-Bildes. Das eigentliche Hero-Bild hat auf keiner Seite ein `fetchpriority`. Gleichzeitig bekommen per Inline-Script alle 38 Marquee-Logos `loading="eager"` und `fetchpriority="high"` gesetzt. Insgesamt sind 55 von 62 `<img>` der Startseite `loading="lazy"`.

**10b. Widersprüchliche Priorisierung der Marquee-Logos.** Wörtlich aus `home.html`:

```js
document.querySelectorAll('.deensimc-image-marquee img').forEach(function (img) {
  img.setAttribute('loading', 'eager');
  img.setAttribute('fetchpriority', 'high');
});
```

Das ist die Signatur eines Fremd-Plugins, die auf jedes Marquee-Bild angewendet wird, unabhängig davon, ob das Marquee überhaupt im Viewport liegt.

**11. `!important` auf einem globalen Font-Override.** Wörtlich:

```css
body,
body * {
  font-family: "Plus Jakarta Sans", sans-serif !important;
}
```

Das überschreibt jede Schrift im DOM inklusive Formularfeldern und Drittanbieter-Widgets. Belegbar sichtbar daran, dass Manrope-Tokens im Kit definiert sind, aber nur in Blöcken mit eigener, höher spezifischer Regel durchkommen (`.haubner-ranking`, `.review-avatar`).

**12. Drei konkurrierende Slider-Systeme.** Swiper 10 vom CDN, Elementor-Swiper 8.4.5 aus dem Plugin und ein handgeschriebener Hero-Slider mit `setInterval` und `classList`. Dazu ein eigenes Marquee-Plugin. Die Wartungslast liegt bei vier Stellen, die dieselbe Aufgabe lösen.

**13. Platzhalter- und Altseiten in der Sitemap.** `page-sitemap.xml` enthält 12 indexierbare Alt- und Platzhalterseiten: `/playground/`, `/playground-2/`, `/vorlagen-seite/`, `/startseite/`, `/kontakt-old/`, `/wertermittlungsrechner-old/`, `/immobilienbewertung-bremen-old/`, `/immobilie-verkaufen-bremen-old/`, `/haus-verkaufen-bremen-old/`, `/wohnung-verkaufen-bremen-old/`, `/kaufen/alle-angebote/haus-kaufen-bremen-old/`. `/blog-old/` steht in der `post-sitemap.xml`. Nicht dazuzählen: `/immobilienmakler-oldenburg/` und `/immobilienbewertung-oldenburg/`, das sind echte Ortsseiten.

**14. Doppelte Frage-Headlines.** Auf der Verkaufsseite steht die H2 "Wie viel ist Ihre Immobilie wert?" und auf der Startseite die H2 "Was ist Ihre Immobilie wert?" (jeweils 1 Treffer). Beide fragen dasselbe, ohne sich inhaltlich zuzuspitzen, und beide konkurrieren mit dem H1 der Rechnerseite: "Was ist Ihre Immobilie in Bremen & Umgebung wert?". Zusätzlich wiederholt die Startseite ihre eigene Frage aus dem Hero weiter unten in Sektion 5 mit einer dritten Variante: "Wie viele Käufer passen zu Ihrer Immobilie?".



### 5. Conversion-Mechanik in 5 Sätzen

Die Seite verkauft keinen Maklerdienst, sondern eine kostenlose Wertermittlung als Einstiegsprodukt. Der Rechner wird an jeder Stelle prominent platziert: als zweite Hero-Spalte auf der Startseite, als Doppel-Block auf jeder Verkaufs- und Standortseite, als eigener Seitenhero, als Menüpunkt "Bewertung" an zweiter Stelle der Hauptnavigation. Die Hemmschwelle vor der Dateneingabe wird durch fünf Microcopy-Zeilen auf der Rechnerseite systematisch abgebaut, die alle dasselbe Versprechen wiederholen: Der Nutzer behält die Kontrolle, es gibt genau einen Kontaktversuch, und der nächste Schritt ist freiwillig. Der Beweis für die Behauptung kommt ausschließlich als Zahl, nicht als Adjektiv: "alle 2 Tage", "22.000+ Suchprofile", "924 Verkäufe", "12 Tage bis zum Verkauf", "+116.000 € über der Hausbank", "300+ Mio. € vermarkteter Wert". Der Ausstieg aus dem Funnel bleibt offen, es gibt immer zwei Wege nebeneinander: Rechner oder direkter Mensch, Bewerten oder WhatsApp, Sofort-Ergebnis oder "Experte buchen". Das Risiko wird vollständig auf die Anbieterseite verlagert und im H1 der Verkaufsseite benannt: "zum vollen Preis, ohne Risiko" plus "Erfolgshonorar: kein Verkauf, keine Kosten".
