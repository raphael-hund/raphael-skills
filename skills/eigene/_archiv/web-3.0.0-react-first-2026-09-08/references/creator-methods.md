## Leon's July design method and Machina's component approach (read in full, 7 Sep 2026)

Leon's [July article](https://x.com/LexnLin/status/2076422557180608888) names three routes: a design skill for speed; component-by-component work for the highest quality (define meaning and audience first, collect references and ask *why* each works, sort them into folders such as Navigation, Heroes, Pricing, Cards, map the structure, then prompt per component: "Create a hero section based on this style, adapted to my branding"); and an inspiration board as the middle path ("Combine the style and direction of these references into a design for my product. Do not copy directly."). He adds custom generated assets with stated colours/style/composition, SVG generation for animatable parts, background removal and layering for depth. MAKE already follows the component route through DESIGN.md and the element inventory; the folder taxonomy is a useful shape for `docs/design/references.md`.

Machina's [August post](https://x.com/EXM7777/status/2092250905655812121) builds "a lego of components": hand the agent library links (beautifului.dev, beui.dev, rareui.com, transitions.dev, ui.shadcn.com), let it fetch the component list and integrate. In MAKE this runs through [ui-libraries.md](ui-libraries.md) and [component-islands.md](component-islands.md) with licence and route checks; rareui.com and transitions.dev have no verified licence file and remain reference-only.
