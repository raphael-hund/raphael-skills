# Inheriting Raphael's web corpus

Use when working from `raphael-hund/raphael-skills` or its client projects. Inspect current source through GitHub and the actual project before combining instructions. Preserve established decisions; this adapter is not permission to rewrite unrelated skills.

The corpus already divides responsibilities between the whole-site `web`, combined visual `design`, and SEO owner `seo`. Its local Taste and Impeccable skills are routers into that design system. Do not load every overlapping upstream as a new controller. [Web](https://github.com/raphael-hund/raphael-skills/blob/main/skills/eigene/web/SKILL.md), [design](https://github.com/raphael-hund/raphael-skills/blob/main/skills/design/SKILL.md), [SEO](https://github.com/raphael-hund/raphael-skills/blob/main/skills/eigene/seo/SKILL.md)

## Preserve these strengths

- Read real ICP, offer, proof and voice; preserve accepted project DESIGN.md/DECISIONS.md and existing URLs unless changes are intentional.
- Plan the complete target sitemap, then each page's visitor job, section purpose, real copy, imagery, responsive structure, action and contextual links. Record build/merge/defer/reject decisions explicitly.
- Build foundations → shared components → page composition. Inspect sections and complete cross-page journeys; keep before/after evidence and independent criticism.
- Maintain a need/source/version/licence/use/verification decision for dependencies and assets. Do not import a whole library for one decorative effect.
- Retain rejection memory: route, rejected asset/pattern, replacement and date. Verify that old rejected material does not reappear.

Sources: [sitemap and sections](https://github.com/raphael-hund/raphael-skills/blob/main/skills/eigene/web/references/sitemap-section-planung.md), [tool router](https://github.com/raphael-hund/raphael-skills/blob/main/skills/eigene/web/references/tool-usecase-router.md), [screenshot critique](https://github.com/raphael-hund/raphael-skills/blob/main/skills/eigene/web/references/screenshot-kritik-loop.md).

## Reconcile inherited assumptions

| Existing assumption | Portable rule |
|---|---|
| Opus-only builder, Grok/Kimi critics, specific external scripts | Use actual Astra/host capabilities and record real agent IDs. Twenty bounded assignments run in supported waves. |
| Multiple `orchestrate`, `ultra-loop`, `ultracode`, Compound controllers | One MAKE lead; choose subordinate capabilities with [dependencies.md](dependencies.md). |
| `/root/clients`, tools/brain directories, browser ports, Adobe kit IDs | Discover project paths, tools and licensed assets. No guessed access from a repository mention. |
| Exactly two dark CTAs, mandatory cards/shadows, repeated page skeletons | DESIGN.md decides by brand and visitor task. Preserve square corners/script/colours when deliberately selected. |
| Fixed uniqueness percentages, inbound-link counts or metadata character blockers | Use distinct useful intent, logical links and current technical evidence; see [seo-pages.md](seo-pages.md). |
| Fixed screenshot dimensions or three-cycle maximum | Inspect meaningful page/state coverage and unresolved defects; avoid repetitive clean checks. |
| Mandatory approval before routine fixes | Follow the existing session's authorisation; ask only for a genuinely material missing decision. |

The historical whole-site Next App Router preference is superseded for new websites by HTML-first output. Actual shadcn components may be rendered at build time or used in bounded React islands through the current [hybrid route](component-islands.md). Preserve a suitable existing Next/React application; a new whole-app conversion still needs its own justification. [Historical stack guidance](https://github.com/raphael-hund/raphael-skills/blob/main/skills/eigene/web/references/radix-shadcn-tailwind-stack.md)
