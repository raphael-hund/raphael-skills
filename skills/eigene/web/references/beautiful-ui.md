# Beautiful UI: AI-interface components and integration

Use [Beautiful UI](https://www.beautifului.dev/) for an actual assistant interface, customer workspace, enquiry wizard, structured progress view or data-review area. Raphael explicitly added it as a preferred reference on 2026-09-07. It complements the service-site references; an ordinary service page does not acquire a chatbot, confidence meter or approval step merely because this library offers one.

## The 21 reference families

These are adapted design/implementation ideas, not claims of tested behavior or measured conversion results. Each link opens the original gallery section.

| Family | Useful mechanism and appropriate application | Production contract |
|---|---|---|
| [Loading State](https://www.beautifului.dev/#loading-state) | Compact activity indicator with elapsed time and alternate visual treatments. | Show real pending activity; elapsed time is not remaining time or percentage complete. Retain a quiet reduced-motion state. |
| [Thinking](https://www.beautifului.dev/#thinking-state) | Collapsible summary with steps, search and coding activity. | Show actual task events or a concise user-facing explanation; do not fabricate reasoning traces or expose private internal chain-of-thought. |
| [Streaming Text](https://www.beautifului.dev/#streaming-text) | Answer, source references, actions and follow-up prompts in one reading flow. | Connect real streaming/error/cancel events, preserve selectable text and scroll position; cite actual sources. Avoid announcing every token to assistive technology. |
| [Approval Card](https://www.beautifului.dev/#approval-card) | One question at a time, contextual choices, optional free text and step navigation. | Use only when the product task needs a decision. Preserve answers, validation and explicit commitment for consequential actions. This is not a new assistant permission gate. |
| [Tool Chips](https://www.beautifului.dev/#tool-chips) | Compact operation/result summaries with detail on demand. | Human-readable task names, actual status and accessible expansion; avoid dumping irrelevant implementation details into customer flows. |
| [Task Rows](https://www.beautifului.dev/#task-rows) | Parent task status with expandable subtasks and capsule/list presentations. | Running, failed, completed and skipped are distinct; completion and progress require real evidence. |
| [Chat](https://www.beautifului.dev/#chat-composer) | Thread tabs, answer context and a composer kept together. | Preserve draft/thread identity, keyboard behavior, actual send state and error recovery. Tabs must not silently lose unfinished input. |
| [Prompt Bar](https://www.beautifului.dev/#prompt-bar) | Text input plus contextual sources, commands, model selection and voice affordance. | Wire only supported functions, distinguish attachment states, handle IME and keyboard menus, and provide genuine microphone/transcription behavior if offered. |
| [Recommendation Card](https://www.beautifului.dev/#recommendation-card) | Recommendation, its key parameters, alternatives and one decision area. | Explain the evidence/uncertainty; decorative confidence is not a calibrated probability. Accept must perform the stated operation or clearly prepare a review. |
| [Context Cards](https://www.beautifului.dev/#context-cards) | Retrieved excerpt with source identity and format. | Retain accurate provenance and access controls; source count and excerpt length are not measures of reliability. |
| [Diff Table](https://www.beautifului.dev/#diff-table) | Before/after changes shown next to their rows and columns. | Keep proposed versus applied distinct; expose accept/reject/undo where appropriate and check stale underlying data before mutation. |
| [Records Table](https://www.beautifului.dev/#records-table) | Structured records, category tags, sorting, relationship status and summaries. | Preserve headers, sort state, null values, useful mobile scrolling and truthful calculations. | [Filter Table](https://www.beautifului.dev/#filter-table) | Status filters with counts beside the table. | Counts correspond to real rows; make current filter, no-results state and reset discoverable. Update without losing focus. |
| [Sidebar Nav](https://www.beautifului.dev/#sidebar-nav) | Workspace navigation and conversation history with collapsible width. | Preserve accessible names/current route in collapsed mode, touch/keyboard operation and an appropriate mobile transformation. Check paid icon dependency. |
| [Search](https://www.beautifului.dev/#search) | Search/command results and a meaningful empty state. | Keyboard selection, Escape and result actions need real semantics; label search scope and distinguish loading, failure and zero matches. |
| [Flowchart](https://www.beautifului.dev/#flowchart) | Trigger, condition and branch relationships represented as nodes. | Supply a readable linear equivalent; actual workflow data determines edges and conditions. Dotted canvas decoration is optional. |
| [Insight Cards](https://www.beautifului.dev/#insight-cards) | A supported takeaway paired with a chart and paged related insights. | Real units/time/source, accessible values and keyboard/touch chart access. The demo's percentages and revenue are not reusable evidence. |
| [Code Block](https://www.beautifului.dev/#code-block) | Code and unified diff with filename, line numbers and copy action. | Preserve exact code, ensure copy feedback reflects success, handle clipboard failure and maintain readable overflow. |
| [Fine-tune Card](https://www.beautifului.dev/#fine-tune-card) | Inspect and adjust explicit properties such as dimensions, radius and opacity. | Real selection, units, allowed ranges, validation and undo; changes must reach the represented object. |
| [Selection Actions](https://www.beautifului.dev/#selection-actions) | Contextual operations on selected text, such as explanation or rewrite. | Preserve selection and original text, include keyboard/touch access, preview replacements and provide recovery; a demo rewrite is not a backend. |

## Reuse through the `@beautifului` registry (React stack)

Follow [component-islands.md](component-islands.md) and the [dependency adapter](dependencies.md). The repository uses Next.js, React, Tailwind v4 and TypeScript. Those are source-stack facts, not a mandate to migrate the website.

1. **Select by job.** Native HTML/custom CSS can implement a static source card or a simple disclosure. For actual React-source reuse, use a compatible static render when there is no required browser behavior; install the item through `@beautifului/<name>` and mark it `"use client"` for real interaction. Merely omitting hydration from a demo does not make its buttons functional.
2. **Inspect the actual registry item before adding.** For example, [approval-card.json](https://www.beautifului.dev/r/approval-card.json) declares foundation, button and glide-menu. The shared Button depends on `class-variance-authority`. Keep one owner for dependency/config changes and preserve customized local components.
3. **Use the documented registry route when implementing in a compatible project.** The README demonstrates `npx shadcn add https://www.beautifului.dev/r/approval-card.json`. This is a later implementation option, not a command executed by this skill update. Inspect target paths, recursive items, dependencies and the CLI's supported diff/dry-run behavior first. Registry delivery alone does not prove project compatibility.
4. **Complete the CSS contract.** Tokens alone do not generate utilities: semantic aliases, Tailwind `@theme` mappings, helper classes, selected keyframes and their fallback rules must reach the built CSS. The registry foundation targets `app/beautifui/foundation.css` (the upstream spelling). Adapt the import/target to the actual project. Prefer the necessary foundation and selected component CSS over pasting a whole unrelated site's stylesheet.
5. **Resolve a concrete registry gap.** The inspected foundation imports `tailwindcss` and `shadow-plugin/unprefixed`, but declares no npm dependencies. Verify the installed Tailwind and shadow-plugin packages, or intentionally replace the shadow dependency with equivalent owned CSS and record that adaptation. Do not promise the CLI resolves every dependency automatically.
6. **Scope and restyle.** Map `--page`, `--canvas`, `--surface`, ink levels, action/status colors, radii and elevation onto DESIGN.md. The foundation has global `:root`, `.dark`, base rules and reduced-motion selectors; importing it wholesale can alter native pages and shadcn tokens such as `--accent`. Inspect reset/cascade, theme inheritance and portals as in the existing island guide. Inter, blue accents, dense labels and dual themes are reference choices, not new site defaults.
7. **Inspect extra packages and rights.** The registry identifies `glimm` for Prompt Bar, `liveline` for Insight Cards and `iconoir-react` for Selection Actions. Sidebar Nav imports a commercial Central Icons package; use existing rights or replace the icons with permitted assets while preserving meaning. The repository's MIT licence (copyright 2026 Shane Levine) does not grant a separate commercial icon licence. Retain the MIT notice for copied/substantial source; no tracking or newsletter service is required for a component.

## Source-specific corrections before production

The README explicitly describes `IceCreamHarness.tsx` as a scripted demo driven by `SCENARIOS` / `matchScenario`. Its recommended provider/backend examples are options. A local widget must connect to the project's actual endpoint and state events; no model, credentials, analytics, newsletter or paid service is installed by this reference.

Two inspected implementation details make that distinction important:

- **ApprovalCard:** `send()` sets its local sent state before calling the optional callback. That is not confirmed delivery. Free-text answers are stored separately in `custom`, while `onSubmitted` receives only the numeric `answers` map. Adapt the payload to include actual text and stable question/option identities, wait for the real outcome and preserve input on failure. The delayed radio auto-advance invokes a closure over state; verify that the final freshly selected answer is included, and avoid automatic commitment for consequential actions. Handle empty questions and rapid back/next/reset when those inputs are possible. These are source-reading findings, not a reproduced runtime test.
- **PromptBar:** the inspected dictation effect appends a fixed `DICTATION` string after a 2.2-second timeout. It demonstrates an affordance; it is not speech recognition. Replace it with real transcription and its permission/error/cancel states, or omit that capability from the product.

Inspect keyframes and JS lifecycle together. A global near-zero-duration reduced-motion rule does not prove that timer-driven behavior, height measurements or focus transitions work correctly. Measured text contrast, target sizes, focus, long German content and responsive behavior still need the [existing screenshot/journey procedure](screenshots.md).
