## 1. Bild A — E-Mail-Hero mit Bergfoto

### 1.1 Header / Nav (A, y 0–80)
- Geometrie: Höhe ~80 px, volle Breite, Bottom-Border 1 px hellgrau (#E5E5E5 geschätzt). Logo links
  bei x≈75, Nav-Links mittig (DOCS, BLOG, PRICING, ABOUT US, Abstand ~28 px), rechts „APP“ als
  Textlink + schwarzer Button „VIEW OUR TEAM →“ (~155×28 px, Padding ca. 12/24).
- Material: Page #FFFFFF; Text #353535 (gesampelt bei DOCS); Button #000000, Text weiß.
- Typografie: Nav-Links Versalien, Sans, ~12–13 px, Tracking +0.04em. Button in Monospace-Versalien
  (A, x 990–1145, y 28–54), ~12 px.
- Button-Form: rechte obere Ecke diagonal abgeschnitten (~8 px Chamfer), kein Radius.
- Nachbau: `<header>` Grid `auto 1fr auto`; Button mit
  `clip-path: polygon(0 0, calc(100% - 8px) 0, 100% 8px, 100% 100%, 0 100%)`.
- Warum: Nav bleibt leise, einziger dunkler Block ist die Aktion. Slop-Risiko: keins, aber
  Versalien-Nav bei mehr als 5 Links wird unruhig.

### 1.2 Rahmen-Schraffur (A, x 0–165 und x 1035–1200, y 80–1000)
- Geometrie: Zwei Seitenzonen je ~165 px breit (A links 80–165 innerhalb einer 1-px-Rahmenlinie,
  ganz außen 0–80 ebenfalls schraffiert). Diagonale Linien 45°, Abstand ~14 px, Strichstärke 1 px.
- Material: Linien sehr helles Grau (~#E8E8E8) auf #FFFFFF. Pixelsample trifft Weiß zwischen den
  Linien, Linie selbst unter Sichtschwelle → Kontrast bewusst minimal.
- Trennung: vertikale 1-px-Linien bei x≈80, 165, 1035, 1120 (A, sichtbar über gesamte Höhe bis
  Logo-Sektion).
- Nachbau: `.gutter{background: repeating-linear-gradient(45deg, #e8e8e8 0 1px, transparent 1px 14px)}`;
  Rahmenlinien per `border-inline: 1px solid #e5e5e5` auf dem Content-Container.
- Warum: Schraffur markiert „außerhalb des Blattes“, Content-Spalte wirkt wie ein Bogen Papier.
  Dekoration bleibt auf den Rand beschränkt (Regel: Textzone ruhig).

### 1.3 Eyebrow-Badge (A, x 435–765, y 157–191)

## 5. Gemeinsamkeiten im Paket

1. Textzone zentriert, ruhig, max-width 480–680 px; Dekoration (Schraffur, Punkte, Verlauf)
   endet, wo der Text steht (A/C/D Schraffur nur außen; D Scrim hinter Text).
2. Produktvorschau als eigene Ebene auf einem „Hintergrund-Material“: Foto (A, C), Stoff (D),
   Verlauf (B). Vorschau immer beschnitten (unten hart in A/D, gefadet in B/C).
3. Reihenfolge fix: Eyebrow → Headline (2 Zeilen) → Subline (2 Zeilen) → CTA-Paar → Vorschau.
   Rhythmus 26–34 px zwischen den Textblöcken, 55–60 px vor der Vorschau.
4. Drei Farbrollen getrennt: Action (Orange #F7562C bzw. Blau #3B7BEA), Daten (Grün/Schwarz in
   A/D, Koralle in B), Motiv (Berg/Wiese/Stoff/Verlauf).
5. Zwei gleich große CTAs, Hierarchie nur über Farbe.
6. Dashboards liefern den Beweis: KPI-Reihe mit Delta, Chart mit Tooltip, Tabs, Sidebar.

## 9. Mobile

Keine mobile Ansicht im Paket. Ableitung: Schraffur-Ränder bei < 900 px entfernen (kosten Breite);
Versal-Headline in B bricht bei 44 px auf 3–4 Zeilen → auf clamp() 30 px senken; CTA-Paar
untereinander stapeln, gleiche Breite behalten.

## 10. Dos

- Deko nur außerhalb der Textspalte (Schraffur, Raster) oder mit Scrim hinter dem Text.
- Vorschau auf eigenem Material, oben per Weiß-Fade an die Textzone anschließen (C, nicht A).
- Kantige Formsprache konsequent: Chamfer an Nav-Button, CTAs, Kasten-Badge (A/C/D).
- Datenfarbe von Aktionsfarbe trennen (A: Orange CTA, Grün Daten; B: Blau CTA, Koralle Daten).
- Headline Medium-Gewicht, Tracking −0.03em, line-height 1.0, ein Akzentwort in Aktionsfarbe.
- KPI-Zellen mit Label / Wert / Delta-Zeile als Beweisformat.

## 11. Don'ts

- Keine zwei gleich großen CTAs mit unklarer Sekundäraktion („JOIN US“).
