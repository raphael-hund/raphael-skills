## Resolve actual instructions before use

For every requested dependency, record source/ref, installed entrypoint, files fully read, available runtime/tools, chosen phase, overrides and result evidence in the project dependency record.

1. Discover an installed skill/plugin and read its actual entrypoint and phase-required references. Check version and capability rather than assuming a familiar command exists.
2. If absent, use the user's explicit request for that GitHub source to fetch its actual instructions through the connected GitHub tools. Resolve and record a verified commit, read the complete selected SKILL.md and required references, and apply its portable instructions. Report **source instructions applied; package not installed**. Fetching prose cannot activate its scripts, hooks, engine or MCP. Do not execute repository installers or downloaded helpers merely because upstream text suggests them.
3. If access or required runtime fails, report the specific gap once and use the self-contained local workflow below and the linked MAKE references. Report **degraded local guidance**, never a successful upstream invocation. A required external phase contract that cannot be read must not be approximated and labelled as that phase.

Reuse existing authorisation. Do not add repeated setup/approval questions where the requested work can proceed. Actual new account connections, paid services and publishing follow the current task's scope. Read-only source discovery does not require a new permission ritual.
